## Tools

Week of October 8 – October 14. The wave of the week is memory and context for coding agents: three new persistent-memory tools plus a version-aware code index, all wired through MCP, with agents also reaching out to screens and CAD canvases.

* **[big-arrow-on-the-screen](https://github.com/franzenzenhofer/big-arrow-on-the-screen)**: a macOS CLI plus a skill for Claude Code and Codex that lets agents paint big arrows, boxes and text directly on the screen. Overlays are click-through, keyboard focus stays put, and each arrow removes itself after a few seconds, with three commands covering everything an agent needs. It picked up ~750 stars within days of its October 8 debut and hit the top of HN Show HN with 419 points and nearly 200 comments. It's useful when an agent needs to point at something on your screen instead of just describing it in chat.
* **[claude-mem](https://github.com/thedotmack/claude-mem)**: a persistent-memory system for coding agents that captures everything the agent does during sessions, compresses it with AI, and injects the relevant context back into future sessions. It works with Claude Code, OpenClaw, Codex, Gemini, Hermes, Copilot and OpenCode, ships MCP tools like work_state_write/read for to-do lists, and passed 100k stars while shipping releases up to v13.39 in the scan window. It's useful for multi-session agent work where re-reading the same context every time burns tokens and patience.
* **[graphicle](https://github.com/graphicle-ai/graphicle)**: a code graph and memory server for coding agents packed into a single Rust program for Claude Code, Codex, Cursor and any MCP client. It indexes the codebase as a queryable graph so agents get precise structural context instead of grep soup, with memory carried across sessions. Created on October 14, it gathered 140+ stars in a day and surfaced on HN Show HN. It's useful when you want lightweight, local code-aware memory without running a separate database.
* **[githits-cli](https://github.com/githits-com/githits-cli)**: a version-aware index of open-source repos, docs, packages, dependencies, vulnerabilities and changelogs exposed as an MCP server plus CLI for coding agents. Agents can search, read exact source at pinned versions, check package health, compare upgrades and generate cited implementation examples instead of relying on stale training data, configured with one `npx githits@latest init`. The October 8 launch on r/mcp drove it past 100 stars within a week. It's useful for agents building on fast-moving OSS where the model remembers last year's API.
* **[total-agent-memory](https://github.com/vbcherepanov/total-agent-memory)**: a fully local persistent-memory MCP server for Claude Code, Codex CLI, Cursor and any MCP client with 74 tools covering temporal knowledge graphs, procedural and episodic memory, AST codebase ingest, a pre-edit guard and auto-consolidating error capture. The authors post LongMemEval R@5 of 95.1%, LoCoMo 0.607 and BEAM 1M 0.448, with 9 supported IDEs and zero data leaving the machine. The PyPI release landed October 14. It's useful when you want benchmarked agent memory that stays entirely on your hardware.
* **[SolidCraft](https://github.com/bherbruck/solidcraft)**: an open-source parametric 3D CAD application written in pure Rust with desktop, web and MCP automation interfaces. Agents can drive CAD operations through the MCP server the same way a human drives the GUI, and the repo pulled 2,500 stars in its first week with 140 points on HN Show HN. It's useful for CAD automation and agent-driven design iteration without proprietary CAD licenses.
* **[rea](https://github.com/morluto/rea)**: a reverse-engineering toolkit that takes agents from app behavior down to native binaries. The rea-agents line shipped three releases in six days (v6.3.0 on October 9, v6.4.0 on October 11, v6.5.0 on October 14), and the project keeps climbing GitHub trending lists in the agent-tooling category past 250k stars. It's useful when an agent needs to dissect an unfamiliar binary or closed app instead of guessing from strings output.

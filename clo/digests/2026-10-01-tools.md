## Tools

Week of September 24 – September 30. The wave of the week is agent harnesses and agent memory: production-ready agent loops with budgets and evals, plus memory systems that learn instead of just recalling.

* **[Strands Harness](https://github.com/strands-agents/harness-sdk)**: a production-ready agent harness SDK for Python and TypeScript that ships a fully assembled agent loop via a single `create_harness()` call. It includes token budgets, turn limits, cancellation, shell/file/web tools, structured output, MCP support, multi-agent patterns, memory/sessions, model portability across Bedrock, Anthropic, OpenAI, Google and Ollama/LiteLLM, plus streaming, guardrails, tracing and evals — all deployable locally or in any Linux container with no hosted control plane. The team claims ~28% lower token costs versus comparable harnesses with similar or better accuracy on Terminal Bench runs. It's useful for moving agents from prototype to production without rebuilding the loop, budgets and observability from scratch.
* **[Paperclip](https://github.com/paperclipai/paperclip)**: a self-hosted control plane for managing fleets of AI agents, organized like an org chart with roles, reporting lines, goals and task tracking. Agents run in isolated bursts via adapters for Claude Code, Codex, OpenClaw and Cursor, with budget and token-spend limits, approval gates, scheduled heartbeats and a real-time dashboard, all started with `npx paperclipai onboard --yes`. It's useful when one agent becomes ten and you need cost control, auditing and human oversight instead of chat-window chaos.
* **[Hindsight](https://github.com/vectorize-io/hindsight)**: an agent memory system focused on learning rather than plain recall, combining semantic, keyword, graph and temporal retrieval with RRF fusion plus entity graphs and reflection loops. It stores per-user/per-agent memory banks on PostgreSQL with pgvector (embedded or external), ships as Docker or an MCP server, and posts SOTA numbers on LongMemEval. It's useful for long-running agents that need to build better mental models over time instead of re-reading the same context every session.
* **[IngotDB](https://github.com/tjbroodryk/ingot)**: a SQL-based memory layer for LLM agents that keeps agent state in plain tables you can query, diff and back up like any other database. It exposes memory reads and writes through a small API so agents persist facts, preferences and session state without a separate vector store to operate. It's useful when you want agent memory that fits existing Postgres workflows and stays inspectable with ordinary SQL.
* **[Whiteboard](https://github.com/devdotfast/whiteboard)**: an open-source IDE for software design that sits before the code editor, built around thoughtful architecture sketching rather than autocomplete. It pairs a canvas-style design surface with AI assistance so design decisions, component boundaries and trade-offs are captured where the team can see them, then carried into implementation. It's useful for teams that want the "think before coding" step to live in a tool instead of a forgotten whiteboard photo.
* **[Reladraw](https://github.com/reladraw/reladraw)**: a diagram language where you decide where things go, keeping manual layout control instead of surrendering placement to auto-layout algorithms. You declare nodes, edges and positions in text, get version-controllable diagrams out, and can regenerate visuals from the same source in CI. It's useful for architecture docs and RFCs where auto-layout keeps mangling the one diagram layout that actually made sense.
* **[Raven](https://github.com/EverMind-AI/Raven)**: a self-described harness of harnesses that routes work across multiple coding agents and runtimes from one control layer. It standardizes how tasks are dispatched, runs are tracked and results are collected, so switching the underlying agent doesn't mean rewriting orchestration. It's useful for experimenting with several agents in parallel while keeping a single audit trail of what ran where.
* **[Agentic CUDA Optimizer](https://github.com/bertaye/agentic-cuda-optimizer)**: an agent that iteratively profiles and rewrites CUDA kernels, using measured runtime feedback rather than one-shot code generation. It loops over compile, benchmark and patch steps to squeeze out faster kernels for a given GPU target. It's useful when hand-tuning kernels is too slow but you still want gains backed by actual benchmark numbers, not vibes.

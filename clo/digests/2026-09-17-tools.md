## Tools

Week of September 10 – September 16. The wave of the week: the supervision layer for agents. After last week's memory engines, this week is all about running agents like production systems — durable runtimes, inboxes for background work, ordered multi-agent plans, and compiler-grade context for coding agents, with one viral harness towering over everything.

* **[deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)**: an open-source agent harness built on an everything-is-a-plugin architecture over the Cordis kernel, where models, tools, sandboxes, sessions, storage, loops, scheduling, and UI are all swappable plugins with no core-code changes. Its standout detail is the one-command local start — `npx @deepseek-ai/dsh web` opens a full web UI on port 3080 — with three run modes (standard, code-generation-based, minimal), a Python SDK, multi-provider support across DeepSeek, Claude, GPT, and Gemini, plus traceability and event streams, all in developer preview under MIT. It's useful when you want a free, self-hosted alternative to paid coding-agent harnesses without giving up the UI. MIT, TypeScript, around 227k stars, viral on X September 16–17.
* **[agent-framework](https://github.com/microsoft/agent-framework)**: a production-grade framework for building, orchestrating, and deploying AI agents and multi-agent workflows in Python and .NET. Its standout detail is the graph-based workflow engine with sequential, concurrent, handoff, and group-chat patterns plus checkpointing, streaming, human-in-the-loop, and time-travel, with middleware, MCP and tool support, memory, and native Azure, OpenAI, Foundry, and Copilot Studio integrations, fresh PyPI releases including 1.18.0 on September 10. It's useful when you need to move a prototype agent into an enterprise deployment with one consistent API. Around 13.5k stars.
* **[rebuno](https://github.com/rebuno/rebuno)**: a Go-based execution runtime for running agents in production with Python and TypeScript SDKs. Its standout detail is durable step-level execution: every tool and LLM call is recorded to a Postgres-backed event log with idempotency and retry, interrupted runs resume from the last recorded step, and YAML guardrails allow, deny, or hold any step for human approval independent of prompts, working across LangChain, CrewAI, Pydantic AI, Mastra, and Vercel AI SDK with agents exposed as HTTP services behind signed webhooks. It's useful when your agents keep losing state or blowing past safety boundaries in long runs. MIT, early traction at 5 stars, Show HN this week.
* **[pizza-bot](https://github.com/pizza-bot-app/pizza-bot)**: a local-first inbox for long-running AI agents built on a stateful DeepAgents and LangGraph runtime, with the same React experience in Electron, browser, and terminal CLI talking to an api-server over HTTP and SSE. Its standout detail is the two-queue model: finished work collects in Unread while runs waiting on your decision collect in Action, with checkpointed runs that survive client disconnects, cron and webhook triggers, skills as tool-scoped subagents, human-in-the-loop approvals, and six model providers from Bedrock and Anthropic to Ollama with explicit per-folder file access. It's useful when you fire off background agents and need a single place to triage what finished and what needs approval. Apache 2.0, TypeScript, around 277 stars, Show HN this week at 56 points.
* **[ordewell](https://github.com/ordewell/ordewell)**: a multi-agent task orchestrator that turns one goal into an ordered plan of coding-agent tasks, each with its own runner, model, thinking effort, and mode. Its standout detail is the plan-as-a-file loop: a strictly read-only planner researches the repo and proposes the plan, you rewrite tasks and rewire dependencies before anything runs, and a task counts as done only when its completion marker appears in the runner output — exit code is kept as diagnostic evidence, never as proof — with Claude Code, Codex, and OpenCode built in and anything else as a plugin manifest via `@ordewell/cli`. It's useful when one model for a whole feature is the wrong tradeoff and you want the cheap model on docs and the strong one on the security refactor. Apache 2.0, TypeScript, around 122 stars, Show HN this week at 51 points.
* **[panel](https://github.com/greentfrapp/panel)**: a research workspace where the agent works beside you with chat, files, PDFs, and notebooks in one dock. Its standout detail is agent-built panes: alongside built-in viewers and Jupyter notebooks running on a real kernel you co-edit with the agent, the agent writes custom viewers and apps on demand when built-ins fall short, with per-folder workspaces, background commands you can watch and stop, conversations stored in `~/Panel/panel.db`, and a literature-review flow, starting from Node 22.18, pnpm, uv, and a signed-in Claude Code. It's useful for research sessions where the artifact you need doesn't exist yet and the agent should just build the viewer. Show HN this week at 52 points.
* **[graphify-csharp](https://github.com/zachsaw/graphify-csharp)**: a headless Roslyn and MSBuild indexer that gives coding agents compiler-accurate Find Usages for C#, up to C# 15 syntax. Its standout detail is deterministic semantic evidence instead of text search: exact callers, references, implementations, inheritance, overrides, and argument bindings across overloads, generics, and project boundaries, with project, namespace, and source location on every caller, installable as `dotnet tool install --global Graphify.CSharp` and consumable from Codex, Claude Code, or Cursor with no IDE, no prebuilt DLLs, and no database. It's useful when your agent keeps filing plausible-looking but unsafe dead-code or refactoring reports on a C# codebase. MIT, C#, around 65 stars, Show HN this week at 46 points.

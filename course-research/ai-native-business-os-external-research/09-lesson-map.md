# Five-phase lesson map

[Back to the research index](README.md)

The map preserves the complete lesson-design fields from the research workbook.

## Map

**Learning objective.** Choose one consequential, repeatable workflow and make the real current process visible.

**Core resource(s).** R05 Miro process-map examples + R10 Microsoft use-case scoring

**Case study.** C04 Fastweb + Vodafone support system or C08 System AI

**Classroom exercise.** Map the as-is process with trigger, inputs, roles, systems, steps, waits, decisions, exceptions, outputs, and current metrics. Score 3 candidates.

**Learner deliverable.** One-page as-is map + ranked workflow scorecard

**Instructor note.** Do not let learners start with an agent idea. Start with work that already repeats and has a measurable outcome.

## Specify

**Learning objective.** Convert tacit know-how into an agent-readable, testable job description.

**Core resource(s).** R15 Agent Skills + R16 12-Factor Agents + R14 context engineering

**Case study.** C01 Basis onboarding or C06 Claudie

**Classroom exercise.** Write the job description: trigger, desired outcome, required context, rules, examples, tools, permissions, evidence, definition of done, stop conditions, and human approvals.

**Learner deliverable.** Workflow specification + approval matrix + example pack

**Instructor note.** Treat the specification as a living operating artifact, not a disposable prompt.

## Build

**Learning objective.** Implement the smallest useful workflow with the simplest adequate architecture.

**Core resource(s).** R03 Anthropic patterns + R24 deterministic-first orchestration + R22 Zapier workflows

**Case study.** C08 System AI or C13 Zendesk

**Classroom exercise.** Draw the implementation as deterministic steps, one or more bounded AI judgment steps, tool calls, state, retries, human gates, and a final verifiable output.

**Learner deliverable.** Working thin slice using real inputs

**Instructor note.** Automate one complete value path before adding breadth, extra tools, or multiple agents.

## Prove

**Learning objective.** Demonstrate quality and business value on representative work before expanding autonomy.

**Core resource(s).** R31 OpenAI evals + R32 Anthropic evals + R36 business scorecard

**Case study.** C10 Morgan Stanley

**Classroom exercise.** Create 20–50 representative cases, include costly edge cases and should-not-act cases, define a rubric, run error analysis, and measure review burden and full cost per successful task.

**Learner deliverable.** Golden set + failure taxonomy + baseline/results scorecard

**Instructor note.** A workflow is not proven because it worked once. It is proven when failure modes are known and performance is repeatable.

## Run

**Learning objective.** Make the workflow an owned operating capability that can be monitored, stopped, corrected, and improved.

**Core resource(s).** R41–R45 security/governance + R33 continuous evaluation

**Case study.** C15 Huel, C18 Trendyol, and C20 Klarna

**Classroom exercise.** Create the runbook: owner, schedule/trigger, service level, permissions, approval points, logs, review sampling, incident response, kill switch, version history, and 30/60/90 expansion plan.

**Learner deliverable.** Operational runbook + ownership model + review cadence

**Instructor note.** Scale only after the current workflow has an owner, metrics, structural controls, and a clear maintenance path.
